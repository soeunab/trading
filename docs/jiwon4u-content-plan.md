- 정해진 운영 원칙: 하루 1편 발행, 일괄 수정 금지, 소개 페이지는 실제 사실만

## 1. 지금 블로그 진단

### 잘하고 있는 것
- **직접 화면을 열어 확인한 기록**: "제 화면에서는 이렇게 보였어요", 직접 만든 스킬 검수 결과 같은 1차 경험이 들어 있다. 구글이 중요하게 보는 "경험(Experience)" 신호다.
- **형식이 좋다**: 첫 문단에 답 → 핵심 요약 → 비교 표 → 단계별 방법 → 꿀팁 → 주의사항.
- **제목에 검색어가 앞에 있다**: "클로드 엑셀 사용법", "클로드 환불" 등.

### 현재 주제 분포

| 묶음 | 글 수(대략) | 예 |
| --- | --- | --- |
| 클로드 기능 설명 | 17 | 스킬, MCP, 프로젝트, 아티팩트, Cowork, 클로드 코드, 크롬, 디자인 |
| 클로드 기본·계정 | 8 | 가입·사용법, 앱·데스크톱 설치, 요금제, 환불, 사용량, 오류 |
| AI 용어 | 5 | MCP, playwright, 로컬 LLM, AI 에이전트 |
| 블로그 자동화 제작기 | 7 | 자동화 프로그램, 카드뉴스, 프롬프트 규칙, 3단계 검수 |
| 분석·실험 | 2 | 제타AI 구조 분석, 같은 프롬프트 3사 비교 |

### 빈 곳
1. **"일을 해결하는 글"이 적다.** 블로그 소개는 "직장인·프리랜서·사회초년생의 업무 활용법"인데, 글은 대부분 **기능 설명서**다. 사람들은 "클로드 스킬"보다 **"회의록 정리 AI"**, **"보고서 빨리 쓰는 법"**을 더 많이 검색한다.
2. **비교·선택 글이 적다.** "챗GPT vs 클로드", "어떤 플랜을 사야 하나"는 결제 직전 검색이라 클릭률이 높다.
3. **자기 경험 글이 묻혀 있다.** 블로그 자동화, 색인 문제 해결, REA 분석은 다른 사람이 쓸 수 없는 글인데 수가 적다.
4. **글끼리 연결해 주는 허브 페이지가 없다.** 내부 링크는 구글이 사이트를 더 자주, 더 깊이 크롤링하게 돕는다(지금 색인 문제와도 연결된다).

## 2. 포지셔닝

> **"클로드로 퇴근을 앞당기는 직장인 실전 노트"**
> 기능 설명이 아니라 **일이 줄어드는 방법**을, 직접 해 본 화면과 결과로 보여 준다.

게으른 빌더가 "개발자식 자동화 시스템"이라면, 지원포유는 **"코딩 몰라도 되는 사무직 업무"**로 차별화한다. 독자가 겹치지 않고, 검색 경쟁도 덜하다.

## 3. 콘텐츠 기둥 5개와 비율

| 기둥 | 비율 | 목적 | 형식 |
| --- | --- | --- | --- |
| **A. 업무별 해결법** | 40% | 검색 유입의 중심 | "○○ 업무, 클로드로 10분에 끝내는 법" + 복붙 프롬프트 |
| **B. 문제 해결(오류·한도·설정)** | 20% | 긴 꼬리 검색어, 급한 독자 | 증상 → 원인 → 해결 순서 |

| **D. 직접 해 본 기록(빌드 인증)** | 15% | 신뢰, 차별화, SNS 공유 | 실패 포함 제작기, 전후 비교 |

하루 1편 기준으로 일주일에 A 3편, B 1편, C 1편, D 1편, E 또는 자유 1편.

## 5. 허브 페이지 3개 만들기

블로거의 정적 페이지(`/p/...`)로 목차 페이지를 만들고 관련 글을 모두 링크한다.

| 허브 | 연결할 글 |
| --- | --- |
| **클로드 처음 시작하기** | 가입·사용법, 앱 설치, 요금제, 사용량, 환불, 오류 |
| **직장인 업무별 클로드 활용법** | A 기둥 글 전부 |
| **클로드 고급 기능 (스킬·MCP·클로드 코드)** | 스킬 2편, MCP, 클로드 코드, Cowork, 크롬, 디자인 |

메뉴와 사이드바에 허브를 고정하고, 새 글을 쓸 때마다 허브에 한 줄 추가한다. 각 글 끝에는 "다음에 읽을 글" 2~3개를 링크한다.

## 6. 글 한 편의 틀

지금 형식을 유지하고 아래 3가지만 더한다.

```
제목: [검색어] + [구체적 결과] + [대상/조건]
     예) 회의록 정리 AI, 클로드로 녹음 텍스트를 결정사항·할 일 표로 바꾸는 법

1. 첫 문단: 결론 2~3문장 (검색한 사람이 바로 답을 얻게)
2. 핵심 요약 3줄
3. 이런 분께 맞아요 / 준비물
4. 단계별 방법 (스크린샷 + 소요 시간)
5. ★ 복붙 프롬프트 박스 (역할·맥락·입력·작업·제약·출력)
6. ★ 실제 결과 (전후 비교, 걸린 시간)
7. 주의사항 (개인정보, 사람이 확인할 부분)
8. 자주 묻는 질문 3개
9. ★ 다음에 읽을 글 2~3개 + 허브 링크
```

## 7. 발행과 배포

| 요일 | 기둥 | 배포 |
| --- | --- | --- |
| 월 | A 업무 | 블로그 → 카드뉴스(인스타·스레드) |
| 화 | B 문제 해결 | 블로그 |
| 수 | A 업무 | 블로그 → 카드뉴스 |
| 목 | C 비교 | 블로그 → 카드뉴스 |
| 금 | A 업무 | 블로그 |
| 토 | D 빌드 기록 | 블로그 → 스레드에 과정 공유 |
| 일 | E 또는 쉬기 | 지난주 글 중 하나를 재가공 |

게으른 빌더에서 가져올 것:
- 카드뉴스 마지막 장에 **"댓글로 '회의록' 남기면 프롬프트 링크 보내 드려요"**. 댓글이 노출을 늘리고, 링크가 블로그 방문과 외부 유입을 만든다.
- 업무 프롬프트 모음을 **PDF로 묶어 이메일 구독 이유**로 쓴다(예: "직장인 클로드 프롬프트 30선").

## 8. 하지 말아야 할 것

- **여러 글을 한꺼번에 수정하지 않는다.** 고칠 일이 있으면 하루 2~3편씩 나눈다.
- **같은 검색어로 비슷한 글을 또 쓰지 않는다.** 예를 들어 "클로드 사용법"은 이미 있다. 새로 쓰기보다 기존 글을 보강한다.
- **확인하지 않은 요금·기능 정보를 쓰지 않는다.** 날짜를 적고 공식 링크를 단다.
- **남의 사이트를 실명으로 비판하는 분석 글은 피한다.** 분석 실습은 내 사이트나 공개 서비스로 한다.

## 9. 성과 확인 (2주마다)

| 지표 | 어디서 | 목표 |
| --- | --- | --- |
| 색인된 글 수 | 서치콘솔 → 페이지 | 2주마다 증가 |
| 노출·클릭이 생긴 검색어 | 서치콘솔 → 실적 → 검색어 | 노출은 있는데 클릭이 적은 글은 제목 개선 |
| 기둥별 평균 클릭 | 서치콘솔 + 글 목록 | 잘되는 기둥의 비율을 늘린다 |
| 카드뉴스 댓글·저장 | 인스타그램 인사이트 | 댓글 키워드 반응이 좋은 주제를 블로그 글로 확장 |

검색어 수요는 서치콘솔 실적과 네이버 키워드 도구로 직접 확인한다. 이 기획안의 "노리는 검색어"는 검색량을 측정한 것이 아니라 가설이다.
