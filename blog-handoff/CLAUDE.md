# 지원포유 블로그 작업 폴더 — 클로드 코드 작업 규칙

이 폴더는 지원포유(https://www.jiwon4u.kr) 블로그 원고를 쓰기 위한 자료 묶음이다.
VS Code에서 이 폴더를 열고 클로드 코드로 작업할 때 이 규칙을 따른다.

## 폴더 구조

| 경로 | 내용 |
| --- | --- |
| `topics.json` / `topics.md` | 글감 49개. ID(T01~T49), 상태, 검색어, 참고 자료, 연결할 기존 글 |
| `research/` | 주제별 조사 자료와 출처 URL. **원고의 사실은 여기서만 가져온다** |
| `data/jiwon4u-posts.csv` | 이미 발행한 글 38편(제목, 주소, 라벨). 내부 링크와 중복 확인용 |
| `data/youtube-60-videos.csv` | "무료 AI 툴" 유튜브 영상 60편 목록(도구, 광고·제휴 신호) |
| `drafts/` | 완성된 원고 초안. 새 원고도 여기에 `YYYY-MM-주소.md`로 저장 |
| `templates/post-template.md` | 원고 틀과 발행 전 체크리스트 |
| `prompts/` | 자주 쓰는 작업 지시문 |

## 원고 작성 규칙

1. **사실은 `research/` 자료와 공식 출처에서만.** 자료에 없는 수치·기능·가격을 지어내지 않는다. 자료에 없으면 `[✅ 확인 필요: ...]`로 표시한다.
2. **직접 경험을 지어내지 않는다.** "제 화면에서는", "직접 써 보니" 같은 문장은 운영자가 실제로 해 본 경우에만 쓴다. 해 보지 않은 부분은 `[📸 직접 캡처: ...]` 또는 `[✍️ 직접 경험 넣기: ...]` 자리 표시로 남긴다.
3. **가격·무료 한도·플랜 조건에는 기준 날짜를 적는다** ("2026년 10월 기준"). 발행 전 공식 페이지 재확인 항목으로 체크리스트에 넣는다.
4. **특정 유튜버·채널·경쟁 블로그 이름을 쓰지 않는다.** 비판이 필요한 경우 "한 영상", "일부 영상"으로 쓴다.
5. **문체**: 해요체. 문장은 짧게. 첫 문단에 결론 2~3문장.
6. **구조**: `templates/post-template.md`를 따른다(핵심 요약 → 표 → 단계 → 꿀팁 → 주의사항 → FAQ → 다음에 읽을 글 → 참고 자료 → 카드뉴스 원고).
7. **내부 링크**: `topics.json`의 `internal_links`와 `data/jiwon4u-posts.csv`에 있는 주소만 쓴다. 새로 지어낸 주소 금지.
8. **검색어 중복 금지**: 같은 검색어를 노리는 기존 글이 csv에 있으면 새 글 대신 "기존 글 보강"을 제안한다.
9. **광고·제휴**: 제휴 링크를 넣지 않는다. 넣게 되면 본문 첫머리에 "광고·제휴 링크 포함"을 표시한다.
10. **AI 생성 이미지**를 쓰면 "AI로 생성한 이미지" 표시를 넣는다.

## 상태 값

| status | 뜻 | 클로드 코드가 할 일 |
| --- | --- | --- |
| `draft_done` | 초안 완료 | 체크리스트 확인, 다듬기 |
| `ready` | 자료 충분 | 바로 원고 작성 |
| `verify` | 공식 확인 필요 | 원고는 쓰되 확인할 사실을 `[✅ 확인 필요]`로 표시하고 목록화 |
| `handson` | 직접 실습 결과 필요 | 실습 순서와 기록 양식부터 만들고, 결과를 받은 뒤 원고 작성 |
| `prompt_design` | 프롬프트 설계 글 | 프롬프트와 가상 예시로 원고 작성, 예시는 "가상"이라고 표시 |

## 작업 후

- 원고를 쓰면 `topics.json`의 해당 항목 `status`를 `draft_done`으로, `draft`에 파일 경로를 적는다.
- 발행하면 `data/jiwon4u-posts.csv`에 한 줄 추가한다.
- 여러 글을 한꺼번에 수정·발행하지 않는다(서치콘솔 색인 문제 때문에 하루 1편 원칙).
